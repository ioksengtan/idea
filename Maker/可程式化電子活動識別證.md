# 可程式化電子活動識別證

記錄日期：2026-09-20  
靈感來源：GitHub Instagram 短片中的 GitHub Universe conference badge  
官方專案：[badger/home](https://github.com/badger/home)

## 點子

把活動識別證從一次性的姓名卡，變成一台可程式化、可互動、活動結束後仍能繼續使用的掌上開發裝置。它同時可以是：

- 姓名與個人資料展示。
- 議程、場地與通知工具。
- 與其他參加者互動的社交裝置。
- 尋寶、闖關與遊戲平台。
- 工作坊教材與 hackathon 開發板。
- 活動結束後帶回家的紀念品。

照片裡上半部仍保留紙本姓名牌與 QR code，下半部是彩色螢幕裝置。這種混合設計很好：入場與身份識別不必依賴電子系統，電子 badge 則專注在互動和可玩性。

## GitHub Universe 的實際做法

照片很可能是 GitHub Universe 2025 的 Tufty Edition badge。GitHub 與 Pimoroni 合作，以 Tufty 2350 為基礎製作客製硬體並預載 MicroPython 應用。

### 2025 版主要硬體

- RP2350，雙核心 Arm Cortex-M33，最高 200 MHz。
- 512 KB SRAM。
- 16 MB QSPI flash。
- 320 × 240 彩色 IPS 螢幕，預設以 160 × 120 邏輯解析度顯示。
- 2.4 GHz Wi-Fi 與 Bluetooth 5。
- 1000 mAh 可充電電池，官方資料標示最長約 8 小時。
- USB-C 充電及程式寫入。
- IR 發射與接收，供場地 beacon、尋寶與遙控互動。
- 五個正面按鍵。
- Qw/ST、SWD 與額外 GPIO 擴充。
- 四區背光、電池電壓與充電狀態監測。
- 聚碳酸酯外殼與掛繩固定點。

### 預載應用

- GitHub profile 統計：avatar、contributions、followers、repositories。
- Flappy Mona 小遊戲。
- 圖片 Gallery。
- Mona 虛擬寵物。
- 使用 IR beacon 的場內尋寶 Quest。
- 像素繪圖工具。

程式以 MicroPython 開發。使用者可以用 USB mass storage 複製 app，或將 UF2 firmware 拖入裝置重新刷寫。系統分成隱藏的預載 `/system` 與使用者可見分區，使用者檔案可以覆寫預載 app，而不必直接修改原系統。

### 2026 的延伸

官方 repository 現已轉向 Universe 2026 badge。它仍以 RP2350B、320 × 240 螢幕、Wi-Fi、電池和 Qw/ST 為基礎，新增：

- LSM6DS3TR-C accelerometer 與 gyroscope。
- IR 收發。
- 方向鍵加 Select、Back、Menu、Home，共八個電容觸控區。
- 五個正面實體控制。
- 可感知 badge 朝向的 logical input API，app 不必硬編碼上下方向。

這表示電子 badge 可以形成逐年演進的平台，而不是每屆活動重新從零設計。

## 最值得參考的設計

### 1. 身份功能與互動功能解耦

紙本名牌即使沒電也能辨識身份，電子裝置故障不會妨礙基本入場流程。電子部分則可以自由重開機、刷 firmware 和實驗。

### 2. 活動本身成為遊戲世界

IR beacon 讓不同會場位置成為 quest 節點。參加者必須實際移動、探索攤位或與人互動，不只是盯著手機完成任務。

### 3. 先提供好玩的預載 app，再開放 hacking

不是每位參加者都會寫程式，因此 badge 開箱就要有完整體驗；想深入的人則能查看範例、修改 app 或加入周邊。這種「零門檻使用、低門檻修改、高上限擴充」的層次值得學習。

### 4. 活動後仍有用途

開源程式、標準 MicroPython、USB-C、Wi-Fi 和擴充接頭，讓 badge 回家後仍可當開發板、桌面資訊面板、遊戲機或遙控器，減少昂貴電子贈品變成電子垃圾。

### 5. 以 simulator 降低開發門檻

Badgeware 生態提供桌面及瀏覽器 simulator。開發者不一定要一直插著硬體，社群也能在沒有 badge 的情況下製作 app。

## 可發展的活動功能

### 名片與社交

- 顯示名字、職稱、興趣與「正在找什麼人」。
- 雙方同意後，透過 QR、NFC、BLE 或 IR 交換聯絡資料。
- 將認識過的人只存本機，活動結束後由使用者自行匯出。
- 顯示可以交談／忙碌／需要協助等狀態。

### 議程與場地

- 收藏 session 並離線顯示個人議程。
- 開場前震動或亮燈提醒。
- 以簡圖顯示場地與下一場位置。
- 即時顯示場次額滿、改場或延遲，但要有離線 fallback。

### 遊戲化

- 場內 beacon 尋寶。
- 與不同興趣的人互動後解鎖圖鑑。
- 工作坊完成後取得數位徽章。
- 團隊合作任務，不以收集個人資料作為必要條件。
- 活動結束後保留成就與虛擬寵物。

### Maker／教育

- 現場教授 MicroPython。
- 開放 app jam，當天開發、當天交換程式。
- Qw/ST／Grove 接頭連接環境感測器、LED、servo 或其他模組。
- 提供網頁 simulator，讓沒有硬體的人也能參加。

## 我們可以做的簡化版本

### 方案 A：M5Stack Badge

用 M5Stack CoreS3、Cardputer 或其他帶螢幕和電池的裝置作為現成硬體：

- 不需要先設計 PCB。
- 使用 UiFlow2、MicroPython 或 Arduino。
- 能快速驗證姓名卡、QR code、議程、互動遊戲與 Wi-Fi 同步。
- 缺點是外型、厚度、按鍵與掛繩方式不像專用 badge。

### 方案 B：RP2350／ESP32-S3 客製 badge

等活動規模和需求明確後，再設計整合式 PCB：

- 2–3 吋低功耗螢幕。
- USB-C、LiPo 充電與保護。
- Wi-Fi／BLE。
- 四至六個按鍵。
- IR 或 NFC 作近距離互動。
- Qw/ST／Grove 擴充。
- 掛繩孔、保護殼和可替換紙本名牌。

ESP32-S3 的生態成熟且整合 Wi-Fi／BLE；RP2350 搭配無線模組則適合延續 Badgeware／MicroPython 類型的架構。

## MVP 建議

第一版不要先做客製 PCB。使用一台現成 M5Stack 或 Pimoroni badge，完成：

1. 首頁顯示姓名、角色與 QR code。
2. 可離線瀏覽活動議程。
3. 以 IR／BLE 找到三個活動 checkpoint。
4. 完成 checkpoint 後解鎖一個角色或 badge。
5. 使用 USB 複製一個自製 MicroPython app。

只要這五件事能讓參加者願意整天佩戴、主動互動並在活動後繼續使用，就值得進入硬體客製化。

## 隱私、安全與營運風險

- 不應持續廣播真實姓名、email 或可長期追蹤的固定識別碼。
- 聯絡資料交換必須由雙方明確操作，最好採短期 token。
- 活動 Wi-Fi 可能不穩，基本功能與遊戲進度應能離線運作。
- firmware、app 與伺服器更新應驗證來源，避免惡意程式散布。
- 電池、充電與外殼必須通過適當安全測試；全天掛在身上的裝置尤其要控制溫度。
- 大量裝置需要編號、燒錄、充電、測試、配對、備品和活動後支援流程。
- 若沒有活動後用途，專用電子 badge 很容易變成電子垃圾。

## 可延伸成的產品概念

### Event OS

硬體只是一個載體，真正可重複使用的是活動平台：

- 統一 app format 與 simulator。
- 議程、地圖、任務和場內 beacon 管理。
- 活動品牌主題與角色素材包。
- 社群 app registry。
- 活動結束後切換成個人開發模式。

### Community Passport

同一個 badge 可以跨多次社群活動使用。每次活動只安裝新的 app／quest，使用者自己保管身份和成就，主辦單位只取得完成任務所需的最小資料。

## 最終判斷

這個點子最有價值的不是「在名牌上放螢幕」，而是將實體活動、開源軟體與社群創作綁在同一個物件上。成功條件是：沒有寫程式的人也覺得好玩，會寫程式的人則能在幾分鐘內修改它；同時基本身份識別永遠不依賴電池或網路。
